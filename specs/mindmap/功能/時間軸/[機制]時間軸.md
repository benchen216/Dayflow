# 範圍

本機制定義時間軸的共同規則：卡片屬於哪一天、哪些卡片會出現、卡片帶哪些內容、使用者的修改與刪除如何影響卡片與觀察、時段評分如何保存，以及閒置一段時間後畫面回到今天。卡片如何產生與被 AI 取代，依 [分析批次與活動卡片](<../AI分析/[機制]分析批次與活動卡片.md>)。

引用本機制的功能：[瀏覽時間軸](<[功能]瀏覽時間軸.md>)、[修改卡片](<[功能]修改卡片.md>)、[刪除卡片](<[功能]刪除卡片.md>)、[評分時段](<[功能]評分時段.md>)、[匯出與複製時間軸](<[功能]匯出與複製時間軸.md>)。

# 時間軸上的一天

1. 一天從早上 4:00 開始，到隔天 4:00 結束；凌晨 0:00–3:59 屬於前一天。
2. 卡片屬於「開始時間所在的那一天」；一張從 3:30 開始、4:20 結束的卡片屬於前一天。
3. 一週從週一開始（週的第一週至少要有 4 天），一週的範圍同樣以 4:00 為界。
4. 「今天」也依 4:00 為界：凌晨 2:00 打開 App，看到的「今天」是前一天。

# 卡片的內容

| 內容 | 說明 |
|---|---|
| 起訖時間 | 以「h:mm AM/PM」的時鐘時間呈現；另存精確的時間點用於排序與計算 |
| 標題、摘要、詳細說明 | AI 撰寫；使用者可改標題 |
| 分類 | 以分類名稱保存（不是分類的身分），使用者可改；系統卡片的分類為 System（失敗卡片）或 Idle |
| 子分類 | AI 撰寫，例如失敗卡片為 Error |
| 分心片段 | 卡片時間內的分心小段，各有起訖時間、標題與摘要 |
| 主要使用的 App／網站 | 主要與次要各一個 |
| 是否由備援產生 | 該批任何一步由備援供應商完成時標記 |
| 縮時影片 | 有產生時記錄影片位置 |

分類以名稱保存：分類改名時既有卡片一併改為新名稱；分類刪除時既有卡片保留原名稱（見[分類](<../分類/[機制]分類.md>)的「分類與卡片的關係」）。

# 哪些卡片會顯示

1. 已刪除的卡片不顯示，也不計入任何統計。
2. 「處理失敗」卡片只在它所屬的批次仍有可用影格時顯示；影格已被清除時隱藏，因為已無法重試。
3. 其餘卡片依開始時間排序顯示。

# 使用者的修改

1. 修改標題：去掉前後空白後不能是空的；空的時不修改。
2. 修改分類：選擇一個分類，卡片保存該分類的名稱。
3. 修改只改變該張卡片；若之後同一段時間被 AI 重新分析（重試、重新處理、或下一批的 45 分鐘改寫範圍涵蓋到它），新的卡片會取代被修改的卡片，修改不會保留。
4. 刪除卡片是標記為已刪除（不移除資料列），同時刪除這段時間的觀察，讓之後的分析不再依據這段內容，並刪除卡片的縮時影片。

# 時段評分

1. 使用者可以把一段時間評為「專注」「普通」「分心」三者之一；評分以時間範圍保存，不綁在卡片上。
2. 新的評分覆蓋與它重疊的舊評分：舊評分落在新範圍外的部分保留，重疊部分被取代。
3. 一張卡片（非 System 類別）有至少 80% 的時間被評分覆蓋時，視為已評分；當天未達 80% 的卡片數就是「待評分卡片數」。
4. 卡片被 AI 重新產生不影響已保存的評分，因為評分屬於時間範圍。

# 閒置後回到今天

1. App 在前景時，若使用者 15 分鐘（可由進階設定覆寫）沒有在 Dayflow 視窗內按鍵、按滑鼠或捲動，標記「需要回到今天」。
2. 下次顯示時間軸時（不在設定頁），切換到今天、清除選取的卡片，並捲動到目前時間。
3. 同一次閒置只觸發一次，直到使用者再次互動。

# 實例化情境

小安在週三 9:00–10:00 有兩張卡片：「修 OAuth 登入」（9:00–9:40，分類 Coding）、「看 YouTube」（9:40–10:00，分類 Distraction）。

| 操作 | 結果 |
|---|---|
| 把「修 OAuth 登入」改名為「修登入 bug」 | 卡片標題更新 |
| 評分 9:00–9:40 為專注，9:40–10:00 為分心 | 兩張卡片都已評分，待評分卡片數減 2 |
| 刪除「看 YouTube」 | 卡片不再顯示，9:40–10:00 的觀察被刪除；分心評分仍保存 |
| 把 Coding 分類改名為 Engineering | 「修登入 bug」的分類變成 Engineering，顏色不變 |
| 重新處理週三 | 卡片全部重新產生，「修登入 bug」回到 AI 撰寫的標題；評分仍在 |
