# 範圍

本機制負責 Dayflow 如何持續擷取螢幕畫面：錄製的狀態、何時擷取、擷取哪一個螢幕、哪些 App 被遮蔽、系統睡眠或鎖定時如何自動停下與恢復，以及擷取失敗與螢幕錄製權限遺失時的處理。擷取到的畫面（下稱「影格」）之後如何被分析成時間軸，由 AI 分析領域負責；影格占用的磁碟空間如何清除，由儲存與資料維護領域負責。

引用本機制的功能：

| 功能 | 操作意圖 |
|---|---|
| [開始與停止錄製](<[功能]開始與停止錄製.md>) | 使用者開啟或關閉錄製 |
| [暫停錄製](<[功能]暫停錄製.md>) | 暫停一段時間或無限期暫停，之後恢復 |
| [設定擷取頻率與解析度](<[功能]設定擷取頻率與解析度.md>) | 調整多久擷取一次、畫面多大 |
| [設定不錄製的 App](<[功能]設定不錄製的App.md>) | 指定哪些 App 的畫面不被記錄 |
| [⚙系統睡眠與鎖定時自動暫停](<[功能]⚙系統睡眠與鎖定時自動暫停.md>) | 系統事件觸發的停止與恢復 |
| [⚙螢幕錄製權限遺失時停止錄製](<[功能]⚙螢幕錄製權限遺失時停止錄製.md>) | macOS 權限不在或擷取持續失敗 |

# Big Picture

## 參與對象

| 對象 | 責任 |
|---|---|
| 使用者的錄製意願（「錄製開關」） | 使用者希望 Dayflow 目前是否在錄製；開關為開時錄製器才會擷取。 |
| 使用者的暫停狀態 | 定時暫停（帶結束時間）或無限期暫停；暫停期間錄製開關為關。 |
| 錄製器 | 依錄製開關實際擷取畫面；另有自己的狀態（閒置、啟動中、擷取中、因系統事件暫停）。 |
| macOS 螢幕錄製權限 | 系統層級的授權；沒有權限時無法擷取。 |
| 影格 | 每次擷取的一張畫面，連同擷取時間、當下使用者已多少秒沒有操作鍵盤滑鼠，保存到本機。 |

## 使用者看到的錄製狀態

使用者在選單列與主視窗看到的狀態只有四種，由錄製開關與暫停狀態共同決定：

| 錄製狀態 | 條件 |
|---|---|
| 錄製中 | 錄製開關為開，且沒有暫停 |
| 定時暫停 | 有定時暫停的結束時間 |
| 無限期暫停 | 處於無限期暫停 |
| 已停止 | 錄製開關為關，且沒有暫停 |

錄製開關為開時不會同時帶有暫停狀態：開始錄製與恢復錄製都會先清除暫停狀態。

## 不能互相推定的事

| 已發生的事 | 不能據此推定 |
|---|---|
| 錄製開關為開 | 正在擷取：錄製器可能因睡眠、鎖定而暫停，或還在等待螢幕、等待重試 |
| 錄製器因系統事件暫停 | 使用者暫停：系統事件結束後會自動恢復，使用者的暫停不會 |
| 擷取了一張影格 | 拍到了真實畫面：前景是不錄製的 App 時，保存的是遮蔽用的替代畫面 |

# 錄製開關的保存

1. 錄製開關的值保存在本機，下次啟動時沿用；但只有在使用者完成新手引導（或已通過新手引導的螢幕錄製權限步驟）後才開始保存。
2. 啟動時，若已通過螢幕錄製權限步驟：
    1. 沒有 macOS 螢幕錄製權限時，錄製開關設為關（不覆寫保存的值），已完成新手引導者看到螢幕錄製權限提示。
    2. 有權限時，錄製開關採用保存的值；從未保存過時預設為開。
3. 尚未通過螢幕錄製權限步驟時，錄製開關維持關，也不保存。
4. 各種改變錄製開關的情境是否寫入保存的值：

| 情境 | 錄製開關 | 寫入保存的值 |
|---|---|---|
| 使用者開始錄製 | 開 | 是 |
| 使用者停止錄製 | 關 | 是 |
| 定時暫停 | 關 | 否（重新啟動 App 後依保存的值恢復錄製） |
| 無限期暫停 | 關 | 是（重新啟動 App 後仍不錄製） |
| 恢復錄製（使用者或定時暫停到期） | 開 | 是 |
| 螢幕錄製權限遺失 | 關 | 否 |

# 擷取設定

1. 擷取頻率：每隔固定秒數擷取一張；可選 1、5、10、20、30、60 秒，預設 10 秒。
2. 畫面高度：每張影格縮放到 720 或 1080 像素高，預設 1080；寬度依螢幕長寬比，寬與高都調整為偶數。
3. 修改擷取頻率時，正在擷取的錄製器立即以新頻率重新計時；修改畫面高度時，下一次擷取就生效。
4. 每次擷取包含滑鼠游標。

# 擷取哪一個螢幕

1. 錄製器只擷取一個螢幕：滑鼠游標所在的螢幕（下稱「目前螢幕」）。
2. 目前螢幕改變時，錄製器在下一次擷取前切換到新螢幕；新螢幕暫時不在系統提供的螢幕清單中時，繼續擷取原螢幕，等清單出現它才切換。
3. 沒有任何可擷取的螢幕時，這次擷取視為「沒有螢幕」的失敗（見「擷取失敗的退避」），一旦重新取得螢幕就立刻擷取，不必等退避時間結束。
4. 螢幕設定改變（接上或拔除螢幕、解析度改變）時重新取得螢幕清單；短時間內連續發生的變化合併成一次查詢。

# 隱私排除的 App

使用者可以指定一份「不錄製的 App」清單（以 App 的識別碼或名稱比對，不分大小寫）。每次擷取：

1. 若當下的前景 App 在清單中，不擷取真實畫面，改保存一張同尺寸的替代畫面，上面標示被遮蔽的 App 名稱；這張替代畫面照常算一張影格。
2. 若前景 App 不在清單中，擷取真實畫面，但把清單中所有正在執行的 App 的視窗從畫面中排除。

第一次開啟隱私設定時，系統會把已安裝的常見密碼管理器與驗證器（例如 1Password、Bitwarden、LastPass、Keychain Access、Authy、Ledger Live 等）自動加入清單一次；之後使用者移除它們不會再被加回。

# 影格的保存

1. 影格以壓縮影片片段的形式保存在本機，每筆影格記錄所屬片段、在片段中的位置、擷取時間，以及擷取當下使用者已多少秒沒有操作鍵盤滑鼠（之後用於閒置判定）。
2. 一個片段在開始 10 分鐘後或累積 600 張影格後關閉，下一張影格開新片段；影格尺寸改變時也會開新片段。
3. 錄製停止、系統即將睡眠或鎖定、App 結束時，正在寫入的片段會被完整關閉，避免遺失最後幾分鐘。
4. 片段無法正常關閉時，該片段的檔案被刪除、其中的影格標記為已刪除。App 啟動時若發現上次最後一個片段已損壞或不存在，同樣把其中的影格標記為已刪除。
5. 擷取請求還在進行時，下一次計時到點會略過，不會讓請求堆積。

# Workflow

錄製器在錄製開關由關轉開時開始工作：

1. 檢查 macOS 螢幕錄製權限。
2. Decision: 是否有權限
    1. Branch: 沒有權限
        1. 依「螢幕錄製權限遺失」處理。
        2. Return: 不擷取。
    2. Else:
        1. 不執行額外動作。
3. 取得系統的螢幕清單，選定目前螢幕。
4. Decision: 取得螢幕清單是否成功
    1. Branch: 失敗，且權限其實已不在
        1. 依「螢幕錄製權限遺失」處理。
        2. Return: 不擷取。
    2. Branch: 失敗，原因是暫時沒有螢幕
        1. 依「啟動重試」的間隔稍後再試一次開始，不計入放棄時間。
        2. Return: 等待重試。
    3. Branch: 失敗，原因是系統擷取服務拒絕
        1. Decision: 系統擷取服務自第一次拒絕起是否已持續拒絕滿 10 分鐘
            1. Branch: 已滿 10 分鐘
                1. 依「持續失敗而放棄」處理。
                2. Return: 不擷取。
            2. Else:
                1. 依「啟動重試」的間隔稍後再試一次開始，等待時間不超過剩餘的放棄時間。
                2. Return: 等待重試。
    4. Else:
        1. 不執行額外動作。
5. 立刻擷取第一張，之後每隔擷取頻率擷取一張，直到錄製開關轉關或系統事件使錄製器暫停。

## 啟動重試

錄製開關為開但無法開始擷取時，依序在 5 秒、30 秒、1 分鐘、2 分鐘、5 分鐘、10 分鐘後重試，之後每 10 分鐘重試一次；使用者開始或停止錄製會取消尚未執行的重試並重新起算。

## 擷取失敗的退避

1. 單次擷取失敗（沒有螢幕，或系統擷取服務拒絕）時，下一次擷取延後：連續第 1 次失敗延後 1 分鐘、第 2 次 2 分鐘、第 3 次 5 分鐘，第 4 次起每次 10 分鐘；延後的那一次之後恢復正常頻率。
2. 任何一次擷取成功就清除連續失敗的次數。
3. 保存影格本身失敗（不是系統擷取服務的問題）時不退避，只略過這一張。

## 持續失敗而放棄

macOS 仍顯示有權限，但系統擷取服務自第一次拒絕起持續拒絕滿 10 分鐘時，錄製器放棄：視同螢幕錄製權限遺失處理（錄製開關轉關、顯示權限提示），不再無限重試。

## 螢幕錄製權限遺失

在任何一步發現 macOS 螢幕錄製權限不在時：停止擷取、錄製開關轉關（不寫入保存的值），並向使用者顯示螢幕錄製權限提示。

# 系統事件造成的暫停與恢復

| 系統事件 | 錄製器 |
|---|---|
| 系統即將睡眠、螢幕鎖定、螢幕保護程式開始 | 停止擷取並關閉片段；若錄製開關為開，進入「因系統事件暫停」 |
| 系統喚醒、螢幕解鎖、螢幕保護程式結束 | 若處於「因系統事件暫停」，等 5 秒後再檢查：螢幕仍鎖定或仍在睡眠時不恢復（等真正解鎖時再恢復）；錄製開關已轉關時不恢復；其餘情況重新開始擷取 |

1. 系統事件不改變錄製開關，也不改變使用者的暫停狀態。
2. 使用者在錄製器「因系統事件暫停」期間關閉錄製，錄製器回到閒置，之後系統恢復也不會開始擷取。
3. 系統喚醒時若使用者的定時暫停已過期，視為暫停到期而恢復錄製（見 [暫停錄製](<[功能]暫停錄製.md>)）；無限期暫停維持暫停。

# 實例化情境

小安把擷取頻率設為 10 秒、畫面高度 1080，並把 1Password 列為不錄製的 App。

| 時間 | 發生什麼 | 結果 |
|---|---|---|
| 09:00 | 開機啟動 Dayflow，上次保存的錄製開關為開，權限正常 | 錄製中，立刻擷取第一張 |
| 09:00–09:30 | 每 10 秒擷取一次滑鼠所在螢幕 | 09:10 時第一個片段開始滿 10 分鐘，下一張進新片段 |
| 09:31 | 打開 1Password 查密碼，它在前景 | 這段期間保存的是標示「1Password」的替代畫面 |
| 10:00 | 選擇暫停 30 分鐘 | 定時暫停，錄製開關為關但保存的值仍為開 |
| 10:05 | 不小心結束並重新開啟 App | 依保存的值恢復錄製（定時暫停只在這次執行中有效） |
| 12:00 | 闔上筆電 | 錄製器因系統事件暫停，片段關閉 |
| 13:00 | 打開筆電並解鎖 | 5 秒後重新開始擷取，錄製狀態仍是錄製中 |
