# 範圍

本機制定義分類是什麼、從哪裡來、怎麼交給 AI，以及分類與卡片、每日目標之間的關係。具體的新增、修改、刪除、排序由本資料夾的功能規格定義；AI agent 修改分類另見 Agent 存取領域。

# 分類的組成

| 內容 | 說明 |
|---|---|
| 名稱 | 顯示在卡片與統計上；卡片以這個名稱對應分類 |
| 顏色 | 以 #RRGGBB 表示 |
| 說明 | 告訴 AI 什麼樣的活動屬於這個分類 |
| 順序 | 可編輯分類依序排列，Idle 永遠在最後 |
| 系統分類 | 不能刪除；目前只有 Idle |
| 是否為 Idle | 標記閒置用的分類 |

分類保存在這台 Mac 上（不在時間軸的資料庫中）。

# 預設分類

1. 從未設定過分類時，預設為 Work（#B984FF）、Personal（#6AADFF）、Distraction（#FF5950）、Idle（#A0AEC0，系統分類），各附預設說明。
2. 新手引導中選擇了職業角色、且使用者尚未自行修改分類時，套用該角色的預設分類（例如軟體工程師：Coding / Debugging、Code Review、Research、Communication、Distraction、Personal），再補上 Idle；同一角色已套用過且分類不為空時不重複套用。角色有：軟體工程師、創業者／主管、設計師、學生、產品經理、資料科學家、其他。
3. 使用者在新手引導中新增、改名、改說明、改色或刪除分類後，視為已自行修改，之後不再自動套用角色預設。

# Idle 分類

1. 分類清單一定有一個 Idle 分類：載入時若沒有，自動補上 Idle（系統分類，排在最後）。
2. 閒置判定直接產生的卡片分類就是「Idle」。

# 交給 AI 的分類清單

每一批寫卡片時，依順序把所有分類（名稱、顏色、說明、是否系統、是否 Idle）交給 AI；Idle 的說明固定為「Use when the user is idle for more than half of this period.」，其他分類的說明空白時不附說明。AI 依這份清單決定卡片的分類名稱。

# 分類與卡片的關係

1. 卡片保存的是分類名稱。分類改名時，把既有卡片上的舊名稱（不分大小寫）一併改為新名稱，舊卡片繼續對應這個分類（程式現況不同，見[修正清單](<../../修正清單.md>) 第 3 項）。分類刪除後，既有卡片仍保留該名稱，但找不到對應分類，因此不再有分類顏色。
2. 之後 AI 新產生的卡片使用新的分類清單。
3. 每日目標保存的是設定當下的分類快照（身分、名稱、顏色），分類之後的修改不回頭改寫已保存的目標；但顯示與計算時會依分類身分對應到目前的名稱與顏色（見[每日目標](<../每日目標/[機制]每日目標.md>)的「沿用上一次的目標」）。

# 實例化情境

小晴是設計師，新手引導時選了「設計師」，得到 Design、Research、Communication、Distraction、Personal、Idle。她把 Research 改名為 User Research、說明改成「訪談與易用性測試」。改名前已經是 Research 的卡片一併改為 User Research，保持原本的顏色；之後產生的卡片也會被 AI 歸到 User Research。她接著刪除 Personal，舊的 Personal 卡片仍顯示 Personal，但沒有顏色。
